Going from a gameengine like Unity or Gamemaker to MonoGame was really weird, so I made this to make my life easier in the future. 

This guide will walk you through the thought process behind writing the framework and the logic requried as well as all the different functions. 
The examples to illustrate how it might be used are based on assignment one, Falling Raindrops. This guide and framework will be updated in the future
if newer functions are needed, but it serves as a good enough base to work off of. 



INTODUCTION------

The idea behind this Engine was the Engine code provides reusable funcitonality and the game code provides the content that uses that functionality. 

The code is split into two folders. For Engine, you should not need to edit it while making a game, however some things like gameobject may need to be edited 
for the sake of ease. For everythign in Initalizer and Game, you should be able edit and write code in there however you choose. 

The ownership chain looks somewhat like this
Game1 (MonoGame's entry point)
Engine (which scene is active)
Scene (list of GameObjects)
Gameobject -> Transform, SpriteRenderer, Animation, Collider

I used the chain to create a pipeline from Game1.Update and Game1.Draw . Monogame calls update and Draw about 60 times per second. The framework passes those calls down the chain. 
Update: Game1.Update -> Engine.Update -> Scene.Update -> GameObject.Update - > Animation.Update
Draw: Game1.Draw -> Engine.Draw -> Scene.Draw -> GameObject.Draw -> SpriteRenderer.Draw



SETUP------

To add a image to the content pipline, open content.mgcb like how you normally add sprites into the game. The asset name used in the SPRITES ENUM is the file name without the extentision,
so things like PlayerIdle0.png become PlayerIdle0. After adding it to content mgcb, add the same name to the sprites enum. So something like:

    public enum Sprites
    {
	    PlayerIdle0, 
	    PlayerIdle1,
	    Raindrop,
	    Door
    }

The spelling and cpailaization must EXACTLY match the asset name. Becuase I wrote AssetManager to load every enum entry at startup, an entry with no matching asset name 
crashes the game when it launches.

To actually draw the texture you also have to register it as a animation. This is because I coded every sprite to actually be a animation. If one wants a static sprite, they should 
register the animation as a single image, and have it loop or not continously loop over that same image. This was done to streamline the process and not have seperate texture and 
animation classes and functions. To register an animation, open GAME1 in internals and go to LoadContent. You should see a labeled spot for adding animation loading. The loading code should
look something like this. 

AssetManager.Instance.LoadAnimation("PlayerIdle", Sprites.PlayerIdle0, Sprites.PlayerIdle1);
AssetManager.Instance.LoadAnimation("Door", Sprites.Door);

The AssetManager keeps a dictionary called aniamtions. Everytime LoadAnimation is used, it adds a entery to that table with a name. For example, for the first LoadAnimation, 
PlayerIdle would be the name with PlayerIdle0 and PlayerIdle1 in the list. If you register a name that already exists, it replaces the old list. LoadAnimation doesn't actually load 
any images. They were already loaded when new Assetmanager(Content) was ran, loading the texture for every entry in the Sprites enum. 

So to actually play the animation, you need to create a GameObject, position it, and play the animation. For instance in Game1 in the Objects location:

    // Realistically you would make a child class of GameObject.
    GameObject door = new GameObject();
    door.Transform.Position = new vector2(740, 430)
    door.Animation.PlayLoop("Door")

Transform position is one of the intial settings for door, along with rotation and size. Position places the sprite, rotation rotates, scale scales sprite texture. However in order to 
see the object drawn, you have to add it to a scene. So in the scene section of Game1, add:

    _engine.CurrentScene.Add(door);

A scene is estianlly a container that holds GameObjects that are currently part of the gaem. You may have things such as a main menu scene, a level one scene, a level two scene, etc. The scene 
owns the list of GameObjects, and scene.Add adds your GameObject to that scene. Currently, the default scene is "defaultScene", but you can change and add more at any time. It should look like
this:

    Scene defaultScene = new Scene();

Note that in the initalize, the engine, _engine, is set towards the "defaultScene." To change that to your new scene you would have to run an engine method that we will go into later
There is no current transfer method built in my me, but since scene is just a List<GameObject>, you can remove an object from one scene and add it to another. 
An object is invisiable until you have called PlayLoop or PlayOnce and one Update has run. Until then it has no texture, so nothing is drawn and it cannot collide. 

An example of a implementation of all the new objects into the engine may look like this:

        protected override void LoadContent()
        {
            _spriteBatch = new SpriteBatch(GraphicsDevice);
            assetManager = new AssetManager(Content);

            Scene defaultScene = new Scene();
            _engine = new Engine(defaultScene);

            AssetManager.Instance.LoadAnimation("PlayerIdle", Sprites.PlayerIdle0);
            AssetManager.Instance.LoadAnimation("PlayerWalk", Sprites.PlayerWalk0, Sprites.PlayerWalk1);
            AssetManager.Instance.LoadAnimation("Ground", Sprites.Ground);
            AssetManager.Instance.LoadAnimation("Raindrop", Sprites.Raindrop);
            AssetManager.Instance.LoadAnimation("Door", Sprites.Door);
            AssetManager.Instance.LoadAnimation("RaccoonWalk", Sprites.RaccoonWalk0, Sprites.RaccoonWalk1);

            SpriteFont scoreFont = Content.Load<SpriteFont>("ScoreFont");

            GameObject ground = new Ground();
            GameObject player = new Player();
            GameObject door = new Door();
            GameObject raccoon = new Raccoon();
            GameObject raindropManager = new RaindropManager();
            _engine.CurrentScene.Add(door);
            _engine.CurrentScene.Add(ground);
            _engine.CurrentScene.Add(player);
            _engine.CurrentScene.Add(raindropManager);
            _engine.CurrentScene.Add(raccoon);
            _engine.CurrentScene.Add(new ScoreDisplay(scoreFont));

            //GameObject.ShowHitboxes = true or false;

        }

CLASS REFERENCES------
Here I want to go into the different classes and what they do. Again, they should not be edited but it is useful information to understanding what you can call or not.

--Engine--
The engine holds the one scen that is currently running and forwanrds Update and Draw to it. It gets this directly from Game1. It includes:
CurrentScene - The active scene (read-only from the outside).
Engine(Scene startingScene) - Creates the engine with the first scene.
Update(GameTime) - Passes Update to the current scene (called by Game1). 
Draw(SpriteBatch) - Passes Draw to the current scene (called by Game1).

Methods
ChangeScene(Scene newScene) - swaps to a different scene immediately
ex. 
    _engine.ChangeScene(door); 

There will always be one engine that exists at a time, so all engines are refered to as _engine. 
ChangeScene now also handles Persistent objects automatically: any object with Persistent == true in the current scene is moved.

The new scene's constructor runs BEFORE the persistent object is transferred in. If a new scene's constructor tries Scene.Find("Player") 
expecting the persistent player to already be there, it won't find it yet - the transfer happens right after construction finishes. 
Look for the player in Update instead of the constructor if you need it that early.

--Scene--
A container for GameObjects. It updates and draws everything inside of it.

Methods
Add(GameObject) - Puts an object in the scene. It starts updating and drawing(next frame if added mid-update).
Remove(GameObject) - Takes an object out. It stops updatign and drawing.
Scene.Find(tag) - First object with that tag, or null. Cast the result: (Player)Scene.Find("Player")
Scene.FindAll(tag) - New list of every object with that tag. Safe to remove from while looping.
Update(GameTime) - Virtual. Updates every object within the scene. 
Draw(SpriteBatch) - Virtual. Draws every object. Updated so now it sorts the draw order by layer. Lower numbers are drawn first, so they appear behind higher numbers. Default is 0.
FindAll(string tag) - Finds all objects with a matching tage and returns them. Useful for things like collisions, as access is needed to other GameObjects that is not readily avaliable, because
of how they were set up in Game1. 
GetPersistentObjects() - Returns every object in this scene with Persistent == true. Used internally by Engine.ChangeScene you shouldn't 
normally need to call this yourself.
GetSolidObjects() - Returns every object in this scene with Solid == true. Used internally by GameObject.validMove.

A specific note about both Update(GameTime) and Draw(SpriteBatch) being virutal. This makes it overrideable if you want scenes such as custom scenes like menu, lobby, whatever. 
To do this you have to make Scene the parrent of your custom scene. For example:

Scene menu = new MenuScene();

This is possible becuase a child class can be treated as its parent. You could then pass in menu into any ChangeScene method. Always call base.Update(gameTime) and base.Draw(spriteBatch)
inside of your overwritten Update and Draw functions, or the objects will stop updating and drawing. 
Other things worth knowing are that adding and removing during Update is safe. The scene loops over a copy of its list. The list of objects in each scene is private. You should 
keep your own references for anything you need to look at. 

To change a scene, you must call 
Scene.NextScene = "Desired scene";
Because at every frame game1 checks if next is empty. If there is a name in next, it will look call build scene and construct a new scene that 
matches the name. This is done so that you can change scenes from anywhere, and not have to worry about passing around the engine reference. This 
is also temperaroy and a better solution will be worked out later. 

--GameObject--
This is the most similar thing I could get to makign a object in GameMaker or Unity. It is the thing you make everything from, and it comes with a Transform, SpriteRender, Collider, and 
Animation already attached. It doesn't come with many methods, but the field is acessed by SpriteRender for most of its funcitonality. 

Transform - position, rotation, and scale. 
SpriteRender - current picture, whether or not it is fliped, and tint. 
Collider - the autogenerated hitbox.
Animation - Plays frame sequences. 
Update(GameTime) - Virtual. Advances the animation and copies the furrent frame into SpriteRender.Texture.
Draw(SpriteBatch) - Virtual. Draws the sprite at transform. 
DrawHitbox(SpriteBatch spriteBatch) - Draws the rectangle of the hitbox for debugging. Draws if DebugDraw || ShowHitboxes is true.
ShowHitboxes - Can be turned to true to debug. Doing so has to be done manually in gameobject, and will show every gameobject hitbox. 
GameObject.Tag - A text label used to find objects. Objects can share a tag.
GameObject.Scene - The scene this object is in (null if none). Set automatically by Scene.Add / Remove.
GameObject.DebugDraw - Can be turned to true to debug. Draws a red rectangle around the hitbox.
GameObject.Layer - The order in which the object is drawn. Lower numbers are drawn first, so they appear behind higher numbers. Default is 0.
Persistent - Bool. If true, this exact object is carried forward into the next scene instead of being left behind when the scene changes. 
Set on Engine.ChangeScene. 
Solid - Bool. If true, other objects calling validMove(delta) cannot move into this object's hitbox. Use for walls, not for things that 
should just be detected/overlapped (use a plain Intersects check instead).
CollisionEnabled - Bool, default true. Intersects() returns false if either object involved has this set to false, letting you turn 
collision off for an object at runtime (e.g. invincibility frames, ghost mode).
deltaTime - preset delta time for easier use within objects. 
List<Component> components - List of components that are added to a gameObject. 
AddComponent(Component component) - Adds a module as a component. 
IsUI - deternimenes if the gameobject is being used for UI or not. If it is, it is rendered seperately to other objects and not used in the camera. 


Just like the scenes, specific gameobjects such as player inherit from GameObject. They would be added to the scene and would need to overide the Update and Draw methods. Always call 
base.Update(gameTime) otherwise the animation never advances and the object stays invisible. Same goes for base.Draw(spriteBatch). An example would be:

    public class Spinner : GameObject
    {
        public override void Update(GameTime gameTime)
        {
            Transform.Rotation += 0.05f;   
            base.Update(gameTime);        
        }
    }

Typical setups for contructors in GameObjects may look like this.
ex.
        public Player()
        {
            Tag = "Player";
            Layer = 1;
            Transform.Position = new Vector2(60, 416);
            startPosition = new Vector2(60, 416);
            Animation.PlayLoop("PlayerIdle");
        }

New addition examples. 
ex.
        wall.Solid = true;

        float dt = (float)gameTime.ElapsedGameTime.TotalSeconds;
        validMove(new Vector2(moveX * speed * dt, 0));
        validMove(new Vector2(0, moveY * speed * dt));

        PlaySound("Hit");

Methods
Intersects(GaemObject other) - This method is a easy way to return true if the objects hitbox overlaps another object's hitbox. That way you wont need Collider.IsColliding, which 
takes five parameters. 
validMove(Vector2 delta) - Moves this object by delta, but checks it against every Solid object in the scene first. If the move would 
overlap a Solid object, the position is reverted and this returns false. Call this instead of directly modifying Transform.Position for 
anything that should respect walls. Call it once per axis (X, then Y) if you want sliding-along-walls behavior rather than getting stuck.
PlaySound(string name, float volume = 1f, float pitch = 0f, float pan = 0f, bool repeat = false) - Plays a sound effect once (or looped, 
if repeat is true). name must match a SoundEffect asset added in the MGCB editor the same way textures are (file name = asset name).

ToggleCollision() - Flips CollisionEnabled on/off.

--Transform--
This class only stores numbers. It tells others where the object is and hwo it looks geometriacally. 

Position - Default is (0, 0). As x increaces, it moves right. as y increaces, it moves down. Position is measured from the center of the sprite. 
Rotation - Default is 0. Angle in radians, and 0 is original position. 
Scale - Default is (1, 1). This is the size multiplier. (2, 2) is double the size. 
ex. 
    player.Transform.Position = new Vector2(100, 440);
    player.Transform.Position += new Vector2(5, 0);  
    player.Transform.Scale = new Vector2(2, 2);       
    player.Transform.Rotation = MathHelper.ToRadians(45);

--SpriteRenderer--
Sprite render holds the picture/texture to draw and knows how to draw it. 

Texture - The current image. This is set automatically by Animation, so you should not set it yourself. 
Effects - Flips the image horizontally or vertically in the other direction. 
Color - Allows for color tint change. Default is Color.White, which means no tint. 
Draw(SpriteBatch, Transform) - Draws the texture (called by GameObject).
FlipHorizontally() - Flips image horizontally.
FlipVertically() - Flips image vertically.
ex. 
    // Face the direction of movement (assuming the art faces right)
    if (moveX < 0) 
    {
        SpriteRenderer.FlipHorizontally();
    }
    else if (moveX > 0) 
    {
        SpriteRenderer.Effects = SpriteEffects.None;
    }
    // Flash red when hit
    SpriteRenderer.Color = Color.Red;

--Animation--
Animation remembers which animation is playing, which frame it's on, and how long that frame has been showing. 
IsFinished - true once a PlayoNce animation reaches its last frame. Always false for loops. 
frameDuration - Seconds each rame is shown. Default is 0.15. It belongs to this objects Animation and it stays set when you switch animations. 
Update(GameTime) - Advances the animation and returns the current frame. 

Methods
PlayLoop(name) - Plays the animation over and over.
PlayOnce(name) - Plays once and then holds the last frame.
Play(name, loop, restart) - The shared mehtod behind both PlayLoop(name) and PlayOnce(name).
CurrentFrame - Returns the index of the currently playing frame (an int). Read-only.

Calling things like PlayLoop("Walk") every frame is safe. If "Walk is already looping, -nothing ever happens- so it doesn't restart. Playing a differetn name replaces the current animation
and starts at frame zero. There is no queue. Calling things like PlayOnce("Attack') is also safe, but it woun't replay once finished. To replay, you have to use Play("Attack", false, true). 
Nothing also automatically returns to another animation. When a PlayOnce finsihes, it holds the last frame until you play something else. If you misname anything, it is not registered with
LoadAnimation and throws a KeyNotFoundException. 
ex.
    // Walk when moving, idle when still (safe to run every frame)
    if (moving)
    {
        Animation.PlayLoop("PlayerWalk");
    }
    else  
    {
        Animation.PlayLoop("PlayerIdle");
    }

    // One-off animation, then go back to idle
    if (hit) 
    {
        Animation.PlayOnce("PlayerHurt");
    }
    if (Animation.IsFinished) 
    {
        Animation.PlayLoop("PlayerIdle");
    }

    // Slower animation
    Animation.frameDuration = 0.3;

--AssetManager--
This loads every image at starup and stores the named frame lists.
Assetmanager(ContentManager) - Loads a texture for every entry in the Sprites enum. Done once in Game1.LoadContent. 
AssetManager.Instance - Global access to the one AssetManager from everywhere. 

Methods
GetTexture(Sprites) - returns the Texture2D for a sprite.
LoadAnimation(name, frame1, frame2, frame3... etc) - Registers a named list of frames. Registering the same name again replaces the old list. 
GetAniamtionLength(name) - How many frames an animation has (used by Animation).
GetAnimationFrame(name, frame) the texture for one frame (used by Animation). 
ex.
    AssetManager.Instance.LoadAnimation("RaccoonWalk", Sprites.RaccoonWalk0, Sprites.RaccoonWalk1);
    AssetManager.Instance.LoadAnimation("Raindrop", Sprites.Raindrop);   
    // still image = 1 frame

Most of the time you will only call LoadAnimation. All the other methods are used internally.

--Collider--
Basically just a rectangel around the sprite. If the rectangle overlaps with another, that means a collicion has taken place and the two objects are touching. 
sizeMultiplier - Default is 80% of the normal sprite size. this controls how big the hitbox is compared to the sprite. 

Methods
GetBounds(Transform, SpriteRender) - This returns the hitbox Rectangle. It is centered on the position of GameObject and is scaled up to match. 
isColliding(transform, renderer, other, otherTransform, otherRenderer) - Returns true if the two hitboxes overlap. GameObject has a more simplified method for this.
BuildNewScene(string name) - hard coded to create a new scene based on the name. This scene is new and is not persistant. To be replaced and improved on in the 
future. 

A list is needed to provide access to other objects before running collision code. This is made possible the Find method listed earlier in scene. 
ex.
    // With the Intersects shortcut from earlier. 

    Player player = (Player)Scene.Find("Player");
    if (player != null && Intersects(player))
    {
        GameState.Score++;
        player.ResetToStart();

        Raccoon raccoon = (Raccoon)Scene.Find("Raccoon");
        if (raccoon != null)
        {
            raccoon.ResetToStart();
        }
     }   

    // Make a forgiving raindrop hitbox (half size)
    drop.Collider.sizeMultiplier = 0.5f;

This hitbox size comes from the current texture, so it follows the objects scale as it is scaled up and down. An object with no texture therefore has a empty hitbox and never collides. 
The hitbox avoids rotation bc I was too lazy to implment that. 

--Timer--
A stopwatch that counts down in seconds based on gametime. You call it every frame, and it tells you whther its still counting.
IsRunning - True if a countdown is in progress

Methods
GameTimer(GameTIme, seconds) - returns true while still counting, and false on the frame it finishes. it then automatically restarts once it is called again.
Reset() - Cancels the countdown, so the next instance of GameTimer call starts fresh. 
ex. 
    // Repeating event: do something every 0.5 seconds.
    //  False means done, so the cekc should be backwards. 
    Timer spawnTimer = new Timer();

    if (!spawnTimer.GameTimer(gameTime, 0.5))
    {
        SpawnRaindrop();   // runs once every 0.5 seconds
    }

    // One-time event: after 8 seconds, do it once
    Timer raccoonTimer = new Timer();
    bool raccoonActive = false;

    if (!raccoonActive && !raccoonTimer.GameTimer(gameTime, 8))
    {
        // the flag stops it from repeating
        raccoonActive = true;   
    }

Every countdowsn has to have its own Timer object. Tow things sharing one Timer will intefere with the other. 

--Input--
A static class that checks for keyboard input. It is a wrapper around Monogame's Keyboard.GetState() and keeps track of the previous frame's state.

Methods
MousePosition() - Returns the current mouse position as a Vector2.
LeftClicked() - Returns true if the left mouse button is clicked.
RightClicked() - Returns true if the right mouse button is clicked.
LeftHeld() - Returns true if the left mouse button is held down.
RightHeld() - Returns true if the right mouse button is held down.
KeyPressed(Keys key) - Returns true if the specified key is pressed.
KeyHeld(Keys key) - Returns true if the specified key is held down.
ex. 
    if (Input.KeyPressed(Keys.Space))
    {
        // Do something once when Space is pressed
    }

Background is a GameObject that draws a texture that fills the entire window. It is meant to be used as a background image for the scene.

Methods 
Background(string animationName, Vector2 position) - Creates a background using the registered aniamtion name aat given position. 
Scene.SetBackground(string animationName) - Adds a background to the current scene at the scene's center.
Scene.SetBackground(string animationName, Vector2 position) - Adds a background at a specific position.

--Tile / Tilemap--
A built-in way to spawn a grid of objects form a text file, without writing a new parsing loop for every level. Tile is a playing textured object, 
which is meant to be inhernented from and swaped for textures, as it scales the texture to the correct size. Tilemap reads a legend file (symbol ->
object type) and a map file (the actualy grid and spawns the right objec for each symbol using a factor function you register per scene. 

-Tile- 
Constructor
Tile(string animationName, Vector2 position, bool solid, int tileSize) creates one plain tile. 

-Tilemap-
Methods
RegisterFactory(string type, Func<Vector2, string, GameObject> factory) - registers what to spawn for a given type name. The factory recieves the 
tiles's pixel position and a optional prameter string from the legend file, and returns the object to spawn. 
Load(Scene scene) - Reads legend.txt and the map file, and spawns every recongized symbol into scene. Must be called after registerFactor for every 
type your legend file actually uses, or those symbols are skipped. 

Legend file format (legend.txt, one line per symbol)
symbol, type, optional parameter
ex. 
    #,Wall,true
    .,Tile,FloorTexture
    P,Player,

ex. 
    public class Level1 : Scene
    {
        public Level1()
        {
            Tilemap tilemap = new Tilemap("level1.txt");

            // #,WallTile,true
            tilemap.RegisterFactory("WallTile",(position, parameter) => new Tile("Wall", position, bool.Parse(parameter)));

            // Example: W,Wall,
            tilemap.RegisterFactory("Wall", (position, parameter) => new Wall(position));

            tilemap.Load(this);
        }
}

WHEN READING FROM A TXT FILE REMEMBER TO CHANGE THE FILE THING IN PROPERTIES TO COPY TO OUTPUT DIRECTORY TO COPY IF NEWER IN PROPERTIES DO IT OR IT DOESNT WORK. 

--DialougeLibrary--
A static key-value store for dialogue lines, reachable from anywhere. Register lines per scene (acting as your "override" per scene just call 
SetLine again with a new id, or reuse an id to overwrite it), and anything can look a line up by id.

Methods
SetLine(string id, string text) - Registers (or overwrites) a line under this id.
GetLine(string id) - Returns the line stored under this id, or "..." if nothing was set.

ex.
    // In a scene's constructor:
    DialogueLibrary.SetLine("rabbit", "I am rabbit.");

    // From any object:
    string line = DialogueLibrary.GetLine("rabbit");

--Game1--
MonoGame's entry point instead of main for some reason. This connects MonoGame to my framework. 
Game1() - Sets up stuff idk.  
LoadContent() - Runs once at startup. Creates the SpriteBatch, the Assetmanager, and all the other content I have labeled for adding. 
Update(GameTime) - Updates both the game engine and Main if you use it. 
Draw(GameTime) - Begins SpriteBatch with PointClamt, draws the engine, and then ends the batch. 

Methods
SetWindowSize(width, height) - Chnages the window size. Only call it once the game is running. The default window is 800 x 480. 
BuildScene(string name) - Builds a new scene and adds it to the sceneCache. Only builds a new scene the first time a request for building is made. 
ResetBuildScene(string name) - Resets a built scene and returns it to the original state. does not affect persistant objects. 

Scenes are no longer rebuilt from scratch on every visit. Game1 keeps a Dictionary<string, Scene> (sceneCache) and BuildNewScene(name) 
only constructs a scene the first time its name is requested; every visit after that returns the SAME Scene instance.

IMPORTANT: because scenes now persist, Scene.NextScene is now reset to "" immediately after being read in Game1.Update, or a cached 
scene will carry its old NextScene value into its next visit and immediately trigger another scene change the moment you return to it. Persistent
objects (GameObject.Persistent) still work the same way on top of this. Theyre for an object that should travel with you into the current 
scene (like the player), which is a different problem than a scene remembering its own leftover state.

MODULAR COMPONENTS------
I made this to make things like adding WASD even easier. Just add the module, such as the movemnt module to allow for WASD movement, or arrowkey
movement for any object. Just going to list them and thier functions here when they are added. 

--BasicMovementModule--
speed - Can set inital speed 
UseWASD - Toggle on and off to use WASD. 
UseArrowKeys - Toggle on and off to use arrow keys. 
UseAD - Toggle on and off to only use A and D. 
ToggleMovement - Toggle on and off to turn off movement entirely. 

Example of modular components being added
ex.

--SceneTransitionModule--
TargetScene - string of the target scene. 
TriggerTag - string of the object that the thing module has to interact with or touch in order to trigger switch. 
TargetPosition - sets position the object would take inside of the new scene. 

ex.
    AddComponent(new SceneTransitionModule{TargetScene = "House", TriggerTag = "Player", TargetPosition = new Vector2(100, 200)});
